## Layering that fits the standards

| Role | Preferred source | Intended use in HCMO |
| --- | --- | --- |
| Upper process semantics | BFO | Anchor a process as a processual entity. |
| Protocol-driven execution, study design, and data transformation | OBI, with its current COB/IAO dependencies | Reuse current specific process classes, plan specifications, specified-input/output relations, study-design semantics, and data transformations where their definitions match. Current OBI process classes use `COB_0000035` completely executed planned process; deprecated `OBI_0000011` must not be used as the active anchor. The execution remains distinct from the plan document. |
| Sensing procedure and execution | SOSA | Represent reusable procedures, executions, observations, sensors, features of interest, and results. |
| Statistical semantics | STATO and the OBI terms used by STATO | Represent specific variables, designs, statistical methods, models, and outputs rather than creating a generic parallel HCMO statistics hierarchy. |
| Execution provenance | PROV-O | Record activities, used/generated entities, association with agents, derivation, and timing without treating PROV-O as the domain upper ontology. |
| Exchange | ISA Process and Bioschemas LabProcess | Serialize an executed process and its protocol, inputs, outputs, parameters, performer, and date. Do not use the exchange type as HCMO's semantic upper class. |

Each modeled workflow must keep three roles distinct:

1. the protocol, plan, procedure, or algorithm;
2. the execution that realizes it; and
3. the record, material, data file, observation result, or statistical result
   generated by that execution.

### Acquisition terminology

Philippe Rocca-Serra's follow-up identified `OBI_0600013` information
acquisition and `OBI_0600010` material acquisition as terms to consider. Review
against the pinned OBI `v2026-05-08` source requires a three-way distinction:

| Intended execution | Candidate semantic source | Boundary |
| --- | --- | --- |
| Procuring an existing physical sensor | [`OBI_0600010` material acquisition](http://purl.obolibrary.org/obo/OBI_0600010) | Fits when possession of a material entity is gained; “material procurement” is an alternative label. |
| Retrieving or copying existing information | [`OBI_0600013` information acquisition](http://purl.obolibrary.org/obo/OBI_0600013) | Fits when possession of information is gained. It explicitly excludes processes that create or change information. |
| Recording new measurements with a sensor | SOSA `Observation`, optionally within [`OBI_0000070` assay](http://purl.obolibrary.org/obo/OBI_0000070) when its evaluant and objective fit | This execution creates observations or data. OBI declares assay disjoint with information acquisition, so it must not be typed as `OBI_0600013`. |

The alternative label “data collection” on `OBI_0600013` must not be used to
collapse retrieval of existing information and generation of new sensor data.
HCMO has no active `SensorAcquisition` class and must not mint one merely to
organize the hierarchy.

## Compatibility findings

These are candidate correspondences for expert review. The table deliberately
does not prescribe `owl:equivalentClass`, `rdfs:subClassOf`, or a SKOS mapping;
the mapping strength must be decided separately for every row.

| HCMO concern | ISA / ISA RO-Crate representation | Candidate semantic source | Finding and future-work constraint |
| --- | --- | --- | --- |
| Protocol or algorithm | Bioschemas `LabProtocol` | OBI plan specification or `sosa:Procedure` | Keep the plan distinct from its execution and identify versioned protocol resources. |
| Sensor-recording execution | Bioschemas `LabProcess` | [`OBI_0000070` assay](http://purl.obolibrary.org/obo/OBI_0000070) when its evaluant/information objective fits, alongside appropriate SOSA execution or observation semantics | A recording execution can use a sensor and generate observations and raw data files. It is not `OBI_0600013` information acquisition merely because “data collection” is an alternative label. Do not force the OBI assay type when its definition is not met. Determine whether a local HCMO specialization is needed only after narrower home-cage semantics and a competency question are approved. |
| Data-processing execution | Bioschemas `LabProcess` with File input and output | [`OBI_0200000` data transformation](http://purl.obolibrary.org/obo/OBI_0200000) | Direct reuse is preferred unless a proposed HCMO class is demonstrably narrower. |
| Statistical analysis execution | Bioschemas `LabProcess` with File input and output | A specific process such as [`STATO_0000218` model fitting](http://purl.obolibrary.org/obo/STATO_0000218) or [`OBI_0000673` statistical hypothesis test](http://purl.obolibrary.org/obo/OBI_0000673) | STATO has no single class that justifies minting an equivalent generic HCMO `StatisticalAnalysis`. Use the most specific justified external process class. |
| Study Factor | ISA Study Factor; the current RO-Crate mapping serializes its value as a `PropertyValue` | [`OBI_0000750` study design independent variable](http://purl.obolibrary.org/obo/OBI_0000750) | The definition of `hcm-bio:StudyFactors` is close, but its logical equivalence and singular/plural IRI history require review. Do not assert a mapping from label similarity alone. |
| FactorValue | Sample `additionalProperty` with `additionalType` `FactorValue` | [`STATO_0000265` factor level](http://purl.obolibrary.org/obo/STATO_0000265) | Strong candidate when the condition is deliberately manipulated. Characteristics not functioning as independent variables remain ISA CharacteristicValues. |
| Measured or dependent variable | Assay `variableMeasured` | [`OBI_0000751` study design dependent variable](http://purl.obolibrary.org/obo/OBI_0000751) and, where applicable, a SOSA observable property | Do not use the independent Study Factor as the assay's measured variable. |
| Experimental group | Subjects or Samples sharing FactorValues | [`STATO_0000193` study group population](http://purl.obolibrary.org/obo/STATO_0000193) | Compare membership, population, and taxonomic constraints before selecting subclass or mapping relations. Do not equate an experimental group with a factor. |
| Animal cohort | No automatic special mapping | [`STATO_0000203` cohort](http://purl.obolibrary.org/obo/STATO_0000203) | Do not reuse this STATO class for generic animal cohorts: its definition is restricted to human beings in a longitudinal design. |
| Experimental-group assignment | ISA Process where represented | [`OBI_0600015` group assignment](http://purl.obolibrary.org/obo/OBI_0600015) and its randomization specializations | Use only when an organism is assigned to an experimental role or group. Cage allocation is not automatically group assignment. |
| Housing assignment | Parameterized ISA Process plus HCMO extension | HCMO housing-assignment record generated by the allocation execution | Accepted: preserve animal, enclosure, allocation execution, and actual time-bounded assignment record as four distinct entities. The process has no fabricated ISA result. |
| Statistical output | ISA Data File produced by a LabProcess | [`STATO_0000039` statistic](http://purl.obolibrary.org/obo/STATO_0000039), [`STATO_0000471` estimate](http://purl.obolibrary.org/obo/STATO_0000471), [`STATO_0000599` point estimate](http://purl.obolibrary.org/obo/STATO_0000599), [`STATO_0000600` interval estimate](http://purl.obolibrary.org/obo/STATO_0000600), [`STATO_0000700` p-value](http://purl.obolibrary.org/obo/STATO_0000700), or a statistical model | Accepted: keep semantic results distinct from their File; use an exact File fragment plus weak `schema:about` exchange link in the evidence profile. |

The reviewed STATO release still gives deprecated `OBI_0000011` as a parent of
`STATO_0000299` statistical inference. HCMO must not rewrite that upstream
axiom. The generic term should be excluded from the first external subset, or
retained only with its exact upstream deprecation context, pending Philippe and
STATO/OBI maintainer review.

## ISA graph and round-trip boundaries

ISA Study and Assay process sequences are directed acyclic graphs. A Process
applies a Protocol to Material or Data inputs and produces Material or Data
outputs. The reviewed ISA RO-Crate draft represents those nodes as Bioschemas
Samples or Files/MediaObjects and omits explicit previous/next-process links as
redundant.

Consequences for HCMO:

- Connect exchange process sequences through explicit Sample and File
  inputs/outputs rather than relying only on a generic process-to-process link.
- Model re-housing as successive allocation executions and successive assignment
  records; do not create a cycle in the ISA graph.
- Preserve a physical enclosure as an HCMO material/equipment entity, not an ISA
  biological Sample.
- Treat a cage identifier as a Process ParameterValue when it is operational
  metadata. Treat a housing condition as a Study Factor only when the study
  deliberately manipulates it.
- Treat a sensor as protocol equipment or an HCMO/SOSA participant, not as the
  biological `object` input of an ISA LabProcess.

The bridge example at `examples/isa-hcmo-bridge.ttl` does not use
`schema:result ex:assignment-1`: the reviewed draft profile expects a
`LabProcess.result` to be a Sample or File/MediaObject. The allocation is
represented as both a Bioschemas `LabProcess` and a `prov:Activity`. It uses the
unchanged animal and enclosure and generates the HCMO assignment record through
PROV, without a `schema:result` assertion.

The same boundary applies to non-file statistical entities. A concrete output
file fits the ISA Process graph. A p-value, estimate, confidence interval, or
fitted model is a separate STATO/PROV entity linked through an exact file
fragment using the accepted weak exchange relation `schema:about`.

## Implemented evidence and remaining external dependency

The repository now contains one deliberately narrow evidence graph:

- a sensor-recording execution typed as Bioschemas `LabProcess`, PROV
  `Activity`, and OBI assay (`OBI_0000070`), producing a raw
  `schema:MediaObject`;
- an OBI data transformation (`OBI_0200000`) from the raw file to a derived
  file and a typed STATO sample mean (`STATO_0000401`);
- a particular HCMO study-factor instance also typed as OBI study design
  independent variable (`OBI_0000750`), a particular factor value typed as
  STATO factor level (`STATO_0000265`), and a particular experimental group
  typed as STATO study group population (`STATO_0000193`); and
- dedicated SHACL checks for the pinned ISA exchange boundary, including an
  injected cyclic process/data graph that must fail.

These are justified types of the example individuals, not mappings between
HCMO classes and external classes. Three competency questions assert the exact
recording-provenance, factor/group, and statistical-result answer rows.

The generated fixture under `examples/isa-roundtrip/` adds a graph-isomorphic
1,539-triple HCMO RDF/extended ISA RO-Crate pair, eight individually housed
animals in a 2 × 2 design, 56 repeated observations, re-housing without animal
identity change, a real derived tissue Sample, a fitted model, estimate,
confidence interval, p-value, and exact result-file fragment. Five additional
competency questions assert authoritative subject-level factor/group values,
housing history, repeated observations, statistical values and meaning links,
and Source/Sample identity. Injected probes reject overlap, orphan or reversed
assignments, incomplete allocation, an unchanged animal as an ISA result, and
an observation assigned to the wrong enclosure. The mixed model is fitted from
the generated activity CSV with pinned numerical dependencies; its model and
active-versus-vehicle contrast at standard enrichment occupy different exact
CSV fragments. A pinned `isatools` 0.14.3 test
executes the native animal Source →
real tissue Sample overlap through ISA-JSON → ISA-Tab → ISA-JSON, preserving
the two HCMO IRIs through explicit ISA comments. The loss contracts explicitly
prohibit fabricated Sample proxies and report subject-level factor assignments,
housing, direct whole-animal recording, groups, repeated observations, and
semantic STATO/file-fragment links as outside that native projection.
