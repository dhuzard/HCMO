\textbf{Pitfalls and FAIRness.} \new{Table~\ref{tab:scans} summarises the ontology scans (service URLs are provided in the references). These findings require careful interpretation rather than automatic correction. OOPS! P10 flags potentially missing disjointness without identifying any affected class pair. Other warnings (P04, P08, P22, P34, P35) mainly concern reused terms from BFO, SOSA, SemTS, QUDT, Schema.org, PROV, and SKOS, whose definitions are covered by HCMO's pinned external-vocabulary contract rather than duplicated in the graph. P13 identifies 37 properties without declared inverses, but adding unsupported inverses would risk false entailments. Similarly, AskWol's mixed-strategy warning reflects HCMO's intentional core-and-module namespace architecture, which we retain. The full triage reports are archived with the evaluation outputs\fnurl{https://github.com/dhuzard/HCMO/tree/main/docs/paper/evaluation}.}

\textbf{Logical consistency.} The canonical RDF/XML artifact of release 0.4.1 was rebuilt and checked on 12 October 2026. HermiT loaded 66 classes and reported zero inconsistent classes.

\textbf{SHACL validation.} The validator supplies the canonical ontology as a separate ontology graph and enables RDFS entailment when validating each example, so that domain, range, and subclass consequences select the same \nolinkurl{sh:targetClass} constraints as explicit types. \new{With the corrected shapes and validator merged after release 0.4.1, three positive examples conform, while the two negative fixtures yield 18 and 5 validation results, respectively. The gate rejects a validation engine failure instead of accepting it as fixture non-conformance. These corrected validation files are not part of the archived 0.4.1 release. A multi-animal probe triggers each of its three group and role rules.} One negative fixture deliberately omits explicit \nolinkurl{rdf:type}: it conforms when validated without the ontology and fails when ontology-aware inference selects the intended targets. This keeps profile requiredness in SHACL rather than in OWL existential semantics. A separate ISA/STATO evidence shape validates the workflow boundary of Sect.~5; an injected process/data cycle is required to fail. \new{For the round-trip fixture, dedicated shapes and injected probes reject inconsistent housing assignments, replacement animals, observation/housing and group/factor mismatches, and fabricated ISA assignment results.}

\textbf{Competency questions.} Twelve SPARQL queries run over the ontology plus all positive examples, and the validator checks the complete expected answer rows, including bindings, unbound values, and multiplicity. All twelve queries match their complete versioned answer sets. \new{They give the same answers on the public endpoint (Sect.~4); running them there exposed a prefix that one query used without declaring it, which rdflib had tolerated, and the validator now rejects undeclared prefixes.}The zero-row dimensions query is intentional: it verifies the absence of missing records rather than being accepted as an unexamined empty result. Five further exact-answer questions run against the isolated round-trip fixture of Sect.~5: nine housing-history rows, eight authoritative subject/group/factor rows, eight per-animal repeated-observation counts, four statistical-result/file-fragment rows including exact values and meaning links, and one Source-to-derived-Sample row.

\textbf{Potential impact.} \new{HCM data exports often lack clear links to the animal, enclosure, environment, equipment, and protocol \cite{bains2025,forrest2026,petit2026wellfair}. By capturing this experimental context and provenance, HCMO can help researchers find, compare, and reuse datasets across systems, provided they are properly mapped and documented. Better data reuse could also reduce unnecessary animal experiments, support secondary analyses, and increase the scientific value of each animal, contributing to Reduction and Refinement \cite{petit2026wellfair}. For AI-assisted research, HCMO provides structured types and relationships that support validation, ontology-aware retrieval, and constrained query generation, although these cannot eliminate incorrect inferences.}

\textbf{Adoption path.} Development is grounded in a network of preclinical and HCM experts originating in COST Action TEATIME, which provides domain feedback and a route to real datasets for validation and uptake. \new{Usage statistics are not yet available, so adoption is a pathway, not a demonstrated outcome.}
