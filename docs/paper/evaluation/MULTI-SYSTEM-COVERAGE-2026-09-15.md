### DVC: three provenance classes in one graph

The DVC graph deliberately mixes measured values (the contributed cohort-7623
export), a synthetic second cohort of female cages, and **declared experimental
metadata** that the export does not carry: light programme (lights off
19:00–07:00), rack temperature and humidity from the rack environmental monitor,
two C57BL/6J mice per cage, weekly Wednesday cage changes, GM500 cages and DVC
Analytics 3.5. Every node of the third kind links to a
`mock-experimental-metadata` dataset note, so a query can separate what was
measured from what was assumed. Supplying that metadata raised DVC coverage from
71 % / 38 % to 85 % / 58 % and made the dark-phase question answerable for the
DVC, which shows how much of an apparent ontology gap was really a metadata gap.

## Competency questions on instance data

Sixteen cross-system questions (`evaluation/queries/`) run over the union of the
ontology and the six graphs (64,444 triples). Fourteen join several systems,
fifteen are fully answered, one has a verified empty answer, and one is partial
for a documented reason: the DVC index is derived by proprietary undocumented
software, so the derivation-procedure question returns rows for the five other
systems only.

Two questions were added with the new systems:

- **MS-15** recovers the *group size* of multi-animal behaviours (2, 3 and 4) by
  counting distinct features of interest per shared `BehaviorResult`, which is
  how an n-ary LMT event survives a shape that admits one subject per
  observation.
- **MS-16** joins touch-screen trial counts, accuracy and mean response latency
  to mouse strain across four strains.

## Finding fixed during the evaluation

The `hcm:RejectedTimelessStateShape` SPARQL constraint used a `VALUES` clause,
which the SHACL specification forbids in SPARQL-based constraints. pySHACL
returned a validation *failure* for any graph containing the deprecated
booleans, and the gate had been counting that failure as non-conformance. The
constraint was rewritten with an equivalent `FILTER (?property IN (...))`; the
edge-case fixture now fails with 18 genuine violations.

## Lessons for 0.4.0 (from `coverage.md` gaps)

Ordered by how much native coverage they cost, largest first:

1. **No task / trial / session vocabulary.** BEATBox scores lowest (34 %
   native): a trial exists only as observations sharing an interval, and the
   task and its schedule are free text on a reused `sosa:Procedure`. The same
   gap affects FED3.
2. **No n-ary behavioural event and no participant roles.** LMT (36 % native)
   stores a social event as one shared `BehaviorResult` observed about each
   participant; who approached whom is lost.
3. **No observation subtype for numeric activity, metabolic or operant
   results** about a subject or group; the generic `sosa:Observation` carries
   them in every system.
4. **No genotype property**; genotype is smuggled in as group membership.
5. **`hcm-bio:ExperimentalGroup` cannot carry strain or sex**, which cage-level
   systems without animal identity need.
6. **`hcm:locatedIn` and arena zones are timeless**, so rack position and zone
   occupancy have no history.
7. **No subject or device identifier property** (`dcterms:identifier` reused);
   no cumulative-versus-interval distinction for quantities.
