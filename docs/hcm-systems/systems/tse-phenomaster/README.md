# TSE PhenoMaster — HCMO coverage example (synthetic export)

- **Vendor:** TSE Systems GmbH (Berlin, Germany)
- **Type:** commercial
- **Modality:** metabolic (open-circuit indirect calorimetry) + feeding / drinking
  load cells + infrared activity frame + body-weight platform + environment
- **Status:** active
- **Chapter reference:** Huzard et al. 2026, commercial platforms (PhenoMaster / AnimalGate)
- **Data provenance:** **synthetic, schema-faithful.** No PhenoMaster export could be
  redistributed for this evaluation, so `datasets/mock/phenomaster_mock_export.csv`
  is generated by [`generate_hcmo_instance.py`](generate_hcmo_instance.py) with a
  fixed seed. Values are plausible but not measured.

## Overview

PhenoMaster is a modular home-cage phenotyping platform: sealed cages ("boxes")
are flushed with air and sampled in turn by a shared O₂/CO₂ analyzer (CaloSys),
while per-box sensors record food and water intake (load cells), locomotion and
rearing (ActiMot infrared light-beam frame), body weight (platform) and box
temperature. The software derives VO₂, VCO₂, the respiratory exchange ratio
(RER) and heat production from the gas differential, and exports one table row
per animal per sampling interval.

## Monitored entities

- **Species:** mouse (rat cages exist; not used here)
- **Housing:** single (one animal per calorimetry box)
- **Enclosure:** bespoke sealed home-cage box; dimensions are **assumed** for this
  synthetic profile (20.7 × 26.7 × 14.0 cm) and flagged as such in the graph

## Sensors & actuators

| Component | Transduces | Sampling | Modelled as |
|---|---|---|---|
| CaloSys gas analyzer (shared) | O₂ (paramagnetic), CO₂ (infrared) of box and reference air | sequential per box | `hcm-tech:Sensor` linked from every box via `hcm-tech:monitoredBy` |
| ActiMot light-beam frame | horizontal (XT+YT) and vertical (Z) beam interruptions | continuous, summed per interval | `hcm-tech:Sensor`, `installedIn` box |
| feeding / drinking load cells | cumulative food (g) and water (ml) | per interval | `hcm-tech:Sensor`, `installedIn` box |
| body-weight platform | body mass (g) | per interval | `hcm-tech:Sensor`, `installedIn` box |
| box temperature sensor | air temperature (°C) | per interval | `hcm-tech:Sensor`, `installedIn` box |

## Data output

- **Format:** semicolon-separated text table with a short header block, one row
  per animal per interval (`Date;Time;Animal No.;Box;…`), units in brackets in
  the column names. The column set is reconstructed from the CalR TSE import
  specification and published supplementary tables; exact vendor header strings
  vary by software version.
- **Interval:** 15 min in the mock (typical 10–30 min); **3 h**, 4 animals, 48 rows.
- **Timestamps:** `dd.mm.yyyy` + `hh:mm:ss` local time, no offset in the export;
  the graph adds UTC+02:00 explicitly.
- **Light schedule:** not in the export; the profile asserts a 12:12 cycle with
  dark from 19:00, so the run spans the light→dark transition.

## HCMO mapping

The complete native-concept → HCMO table is [`hcmo-mapping.tsv`](hcmo-mapping.tsv)
(27 concepts; coverage is computed by `tooling/evaluate.py`). Highlights:

- **Native subtypes fit:** body weight → `hcm-obs:WeightObservation`; box
  temperature → `hcm-obs:EnvironmentObservation`; O₂/CO₂ →
  `hcm-obs:GasConcentrationObservation`; target temperature →
  `hcm-env:MeasurementSpecification`; the 12:12 schedule → `hcm-env:LightCycle`.
- **Generic pattern (partial):** VO₂, VCO₂, RER, heat, food, water, beam breaks
  and rearing counts are `sosa:Observation` instances about the subject with
  `hcm-obs:QuantityValue` results and `sosa:usedProcedure` pointing to the
  calorimetry procedure, because HCMO 0.3.0 has no metabolic or activity
  observation subtype.
- **Deliberately out of scope:** reference-air channels and the flow setting
  (device operating parameters).

**Gaps exposed** (see the coverage report): no subject-identifier property
(`dcterms:identifier` reused); no distinction between cumulative and interval
quantities; no HCMO unit for kcal/h (QUDT's thermochemical `KiloCAL_TH-PER-HR`
is used); a shared sensor cannot be `installedIn` any single enclosure and is
linked only through `monitoredBy`.
