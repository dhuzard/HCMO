# Live Mouse Tracker (LMT) — HCMO coverage example (synthetic database)

- **Authors:** de Chaumont et al. (Institut Pasteur) — [micecraft.org/lmt](https://micecraft.org/lmt/)
- **Type:** open-source (hardware design + `lmt-analysis` Python package)
- **Modality:** infrared depth video (Kinect v2) fused with RFID identity, group-housed
- **Status:** active
- **Chapter reference:** Huzard et al. 2026, open-source systems (Live Mouse Tracker)
- **Data provenance:** **synthetic, schema-faithful.** No LMT recording could be
  redistributed for this evaluation, so the tables under `datasets/mock/` are
  generated by [`generate_hcmo_instance.py`](generate_hcmo_instance.py) with a
  fixed seed. Their **column layout and event names are taken from the
  `lmt-analysis` sources**, so the mapping is exercised faithfully; the
  positions, sensor values and events are not recorded data.

## Overview

LMT tracks a group of RFID-tagged mice living together in one cage. A Kinect v2
depth camera above the arena segments the animals at 30 frames/s, a grid of RFID
antennas under the floor maintains each animal's identity across the recording,
and the tracker writes a single SQLite file. The `lmt-analysis` package then
rebuilds a vocabulary of behavioural events — individual (move, stop, rear, zone
occupancy), dyadic (contact, oral-oral and oral-genital contact, social approach,
follow, train of two) and group events (groups of 2, 3 and 4, nest building) —
from the per-frame detections.

## Scenario in this example

| | |
|---|---|
| Arena | one 50 × 50 cm open-top cage, house + nesting material |
| Animals | **4 males**, strain `B6.129-Shank3tm2Gfng/J` (Shank3), **2 WT + 2 KO** |
| Camera | Kinect v2, 30 frames/s |
| Identity | 16 RFID antennas in a 4 × 4 grid under the floor |
| Light cycle | 12:12, dark from 19:00 |
| Experiment | 30 days from 2026-05-12; **bedding change every 10 days** |
| Materialised window | 10 min at full rate, 18:55–19:05, spanning the light→dark transition |

## Data output

The mock reproduces the four tables that `lmt-analysis` reads:

| Table | Columns | Rows in the mock |
|---|---|---|
| `ANIMAL.csv` | `ID, RFID, NAME, GENOTYPE, AGE, SEX, STRAIN, SETUP` | 4 |
| `FRAME.csv` | `FRAMENUMBER, TIMESTAMP, PAUSED, NUMPARTICLE, TEMPERATURE, HUMIDITY, SOUND, LIGHTVISIBLE, LIGHTVISIBLEANDIR` | 18,000 |
| `DETECTION.csv.gz` | `ID, FRAMENUMBER, ANIMALID, MASS_X/Y/Z, FRONT_X/Y/Z, BACK_X/Y/Z, REARING, LOOK_UP, LOOK_DOWN, DATA` | 72,000 |
| `EVENT.csv` | `ID, NAME, DESCRIPTION, STARTFRAME, ENDFRAME, IDANIMALA..IDANIMALD, METADATA` | 288 |

- **Time base:** `FRAME.TIMESTAMP` is epoch milliseconds; events and detections
  reference `FRAMENUMBER`, so every absolute time in the graph is resolved
  through the FRAME table.
- **Coordinates:** depth-image pixels; the pixel-to-cm scale (0.125 cm/px for a
  50 cm arena over 400 px) is recorded in `ANIMAL.SETUP`, not in the rows.
- **Real files:** a genuine LMT database is a single `.sqlite` file. The
  generator writes one with `--sqlite PATH`; it is **not committed** because its
  bytes depend on the SQLite build, whereas the CSV dumps are byte-stable.

## HCMO mapping

The complete table is [`hcmo-mapping.tsv`](hcmo-mapping.tsv) (35 concepts).
Highlights:

- **Fits HCMO:** arena, enrichment, housing over the 30-day experiment, Kinect
  and RFID antennas as sensors, the two software layers, the four tables as time
  series, arena temperature and humidity as `hcm-obs:EnvironmentObservation`,
  individual events as `hcm-obs:BehaviorObservation` with the **exact
  lmt-analysis event names** as `hasBehaviorType`, and per-animal detection
  tables as `hcm-obs:LocationResultTable` with SemTS dimensions.
- **Group events are the interesting case.** `hcm-obs:BehaviorObservation`
  requires exactly one `sosa:hasFeatureOfInterest`, but LMT events carry up to
  four participants (`IDANIMALA..D`). We emit **one observation per participating
  animal, all sharing a single `BehaviorResult`**, so the event stays one thing
  in the graph while every participant is queryable. The participant **roles**
  (who approached whom) survive only as a `dcterms:description` on the result.
- **Genotype has no home.** WT/KO is expressed as membership of an
  `hcm-bio:ExperimentalGroup`, which cannot be distinguished from any other
  grouping.

**Gaps exposed** (fed into `evaluation/reports/coverage.md`): no participant
roles and no n-ary behavioural event; no genotype property; sound and light
indices have no physical unit; per-frame posture flags (`REARING`, `LOOK_UP`)
have to ride along as table dimensions; the RFID grid geometry and the
identity-fusion dependency between antennas and tracker cannot be stated.
